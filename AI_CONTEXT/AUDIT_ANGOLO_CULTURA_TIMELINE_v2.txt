Snapshot URL/path conservati in report. Non sulle suggestion in review. |

### Review architetturale flusso foto (2026-08-27)

#### Gap trovati (pre-fix)

| # | Gap | Impatto |
|---|-----|---------|
| G1 | Assente Storage RLS INSERT per `famous_person_photo_suggestions/{uid}/` | Upload UI falliva (RLS deny su `public-media`) |
| G2 | RPC accettava `storage_path` arbitrario (Patron, altri utenti, altre cartelle) | Spoofing path via chiamata diretta RPC |
| G3 | Assente Storage RLS DELETE admin sull’area Famous Person | Cleanup amministrativo impossibile lato Storage |
| G4 | `deletePublicMediaByStoragePath` non riconosceva prefisso Famous Person | accept replace / photo_blocked non eliminavano file |

#### Correzioni effettuate

| Gap | Fix |
|-----|-----|
| G1 | Policy `public_media_famous_person_suggestions_user_insert` in migration F6 §9 |
| G2 | Check RPC `v_storage_path NOT LIKE ('famous_person_photo_suggestions/' \|\| v_uid \|\| '/%')` → EXCEPTION |
| G3 | Policy `public_media_famous_person_suggestions_admin_delete` in migration F6 §9 |
| G4 | Whitelist `famous_person_photo_suggestions/` in `src/services/mediaService.ts` |

#### Nuova review end-to-end (post-fix)

| Step | Esito |
|------|--------|
| UI upload → `famous_person_photo_suggestions/{userId}/{ts}_{file}` | Autorizzato da Storage INSERT policy (segmento `[2]` = `auth.uid()`) |
| Path servizio ↔ policy | Allineati (`famousPersonPhotoSuggestionService.ts` folder = policy prefix + uid) |
| RPC diretta con path altrui / Patron / gallery | **Rifiutata** (check prefix uid) |
| INSERT tabella suggestion | Solo RPC SECURITY DEFINER; tabella senza INSERT policy utente |
| Admin accept → `city_people.image_url` + `image_storage_path` | Una sola foto; UPDATE sostitutivo |
| Replace foto ufficiale precedente | `deletePublicMediaByStoragePath` se path sotto prefissi ammessi |
| Abuse → photo_blocked | Clear DB + delete Storage se path Famous Person noto |
| Abuso RLS | URL + storage path + snapshot names vs sorgenti reali (invariato) |

**Limitazione nota (non bloccante, parità Patron):** la RPC non verifica che `image_url` derivi deterministicamente da `storage_path`; il vincolo operativo è prefix path + upload controllato. Reject suggestion non cancella file Storage (orphan possibile; stesso comportamento Patron).
